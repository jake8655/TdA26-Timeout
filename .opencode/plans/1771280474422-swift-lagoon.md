# Plan: Migrate file storage into Java backend (apps/server only)

## Goal
Move file storage from the Bun service into the Java Spring backend, keeping upload logic internal to course material creation. Store files on the filesystem with allowed extensions + 30MB limit, serve files via `/uploads/**`, add a `just` command to clear uploads, and ensure it works locally, in Docker, docker-compose, and Tour de Cloud.

## Scope
- Touch only Java backend and supporting infra:
  - `apps/server/src/main/java/eu/hypnomacka/timeout/server/controllers/course/materials/MaterialPostController.java`
  - `apps/server/src/main/java/eu/hypnomacka/timeout/server/controllers/course/materials/MaterialPutController.java`
  - `apps/server/src/main/java/eu/hypnomacka/timeout/server/controllers/course/materials/MaterialDeleteController.java`
  - New storage service class (e.g. `apps/server/src/main/java/eu/hypnomacka/timeout/server/storage/FileStorageService.java`)
  - New web config for static file serving (e.g. `apps/server/src/main/java/eu/hypnomacka/timeout/server/config/FileStorageConfig.java`)
  - `apps/server/src/main/resources/application.properties` (uploads dir + multipart limit)
  - `apps/server/Dockerfile`
  - `compose.yaml`
  - `apps/server/justfile`

## Plan
1. **Create file storage service**
   - Add `FileStorageService` to handle:
     - Allowed extensions list (same as Bun: `.pdf`, `.docx`, `.txt`, `.png`, `.jpg`, `.jpeg`, `.gif`, `.mp4`, `.mp3`).
     - Max file size (30MB).
     - Filename normalization + unique naming:
       - Preserve original extension (lowercased).
       - Normalize Unicode filename to NFC or NFKC for stability.
       - Strip/replace unsafe path chars, collapse whitespace, and trim.
       - Use the agreed structured name: `<yyyyMMdd>/<courseUuid>/<ulid>.<ext>` (optionally prefixed with a safe, short slug for readability).
       - Ensure final filename is safe for filesystems and URLs, and capped to a sane length.
     - Directory creation on demand.
     - Save file bytes to disk under `UPLOADS_DIR`.
     - Delete file on disk (for material replace/delete).
   - Read `UPLOADS_DIR` from env/system properties with a default (e.g. `./uploads`).

2. **Serve files via `/uploads/**`**
   - Add a Spring `WebMvcConfigurer` to map `/uploads/**` to the filesystem location.
   - Ensure paths are safe (no traversal) by serving only from the configured root.
   - File URL stored in DB should be `/uploads/<filename>` (relative to server base).

3. **Update course material controllers to use local storage**
   - `MaterialPostController`: replace WebClient upload to CDN with `FileStorageService.store(...)` and set `fileUrl` to `/uploads/<filename>`.
   - `MaterialPutController`:
     - Keep metadata updates as-is.
     - When file replaced, delete old disk file via `FileStorageService.delete(...)` and store new file via service.
   - `MaterialDeleteController`: remove CDN delete call and delete stored file from disk before removing DB record.
   - Remove API key usage + CDN_URL dependency in these controllers (no more WebClient calls).

4. **Configuration updates**
   - Set `uploads.dir` (or equivalent) in `application.properties` with env override.
   - Enforce 30MB limit in custom logic only (no Spring multipart size limits in properties).
   - Ensure existing Dotenv loading still works for `UPLOADS_DIR`.

5. **Docker + compose support**
   - Update `apps/server/Dockerfile` to create an uploads directory and ensure the `spring` user can write to it.
   - In `compose.yaml`, add `UPLOADS_DIR` for `server` and a volume (bind or named) to persist files, e.g. `./uploads:/data/uploads`.
   - Keep persistence optional; `docker compose down -v` should clear uploads when a named volume is used.

6. **Just command**
   - Add `clear-uploads` to `apps/server/justfile` to wipe the local uploads directory (matching the chosen default path).

## Verification
1. Local:
   - `just clear-uploads`
   - Run the server, upload a material, verify file exists in `UPLOADS_DIR` and `fileUrl` is `/uploads/<filename>`.
   - Replace a material file; confirm old file removed and new file stored.
   - Delete a material; confirm file removed.
2. Docker Compose:
   - `docker compose up --build`
   - Upload a material and confirm file appears in the mounted uploads path.
   - `docker compose down -v` removes uploads.
3. Tour de Cloud:
   - Deploy with `UPLOADS_DIR` set; upload + fetch a file via `/uploads/<filename>`.
