# Plan: Course lifecycle, scheduling, visibility, join, kick-out

## Goals
- Add 5 course states (draft, scheduled, live, paused, archived) with Bratislava-time scheduling and auto transitions.
- Restrict public visibility: scheduled/paused appear in listing only (no detail content), live is fully visible, draft/archived are hidden.
- Add manual join action to mark participants; only participants can see archived results.
- Broadcast destructive actions (pause/end/delete) to connected students with a reason and kick them out immediately.
- Support course duplication in any state into a new draft with a rename dialog.

## Phase 1: Backend model + data

### Data model updates
- Update `apps/server/src/main/java/eu/hypnomacka/timeout/server/core/Course.java`
  - Add `status` enum (DRAFT, SCHEDULED, LIVE, PAUSED, ARCHIVED).
  - Add scheduling fields: `scheduledStartAt`, `scheduledEndAt`, `pausedAt`, `archivedAt` (Instant).
  - Add `lastWentLiveAt` if needed for audit/display.
- Add new entity `CourseJoin` (manual join tracking), stored by student session token.
  - File: `apps/server/src/main/java/eu/hypnomacka/timeout/server/core/CourseJoin.java`.
  - Fields: `uuid`, `course`, `sessionToken`, `joinedAt`, `lastSeenAt`, `active`.
- Add migration in `apps/server/src/main/resources/dbmigration/1.9.sql` (or next available):
  - Alter `courses` table with status + schedule columns.
  - Create `course_joins` table with indices for course+session.

### Scheduling + auto transitions
- Implement scheduled transitions in backend using a Spring scheduled job (enable scheduling):
  - New config: `@EnableScheduling` in a config class.
  - New service: `apps/server/src/main/java/eu/hypnomacka/timeout/server/services/CourseLifecycleService.java`.
  - Runs every minute:
    - `scheduled -> live` when `now >= scheduledStartAt`.
    - `live|paused -> archived` when `now >= scheduledEndAt`.
  - Use `ZoneId.of("Europe/Bratislava")` for comparisons; store times as UTC Instant.
  - Create system `Event` for status changes.

## Phase 2: Backend API + validation

### Course state endpoints
- Extend existing course responses to include status + schedule fields.
- Add new endpoints for state transitions and scheduling:
  - `PUT /courses/{courseId}/status` with body `{ status, scheduledStartAt?, scheduledEndAt? }`.
  - `PUT /courses/{courseId}/schedule` for draft/paused transitions to scheduled with start/end.
  - `POST /courses/{courseId}/start` for immediate live (requires end time).
  - `POST /courses/{courseId}/pause` with optional future restart/end.
  - `POST /courses/{courseId}/archive` to finalize.
- Apply validation rules per state as defined by user:
  - Only draft allows course edits and content changes.
  - Scheduled/paused updates allow only schedule changes.
  - Live allows pause; paused allows restart or archive.
- Implement in controllers:
  - `apps/server/src/main/java/eu/hypnomacka/timeout/server/controllers/course/CoursePutController.java` (extend to enforce edit constraints).
  - Add new controller(s) under `controllers/course` for lifecycle actions.

### Visibility gating
- Update `CourseGetController`:
  - Public list returns only `scheduled`, `live`, `paused` with minimal fields for scheduled/paused.
  - Public detail returns:
    - live: full payload
    - scheduled/paused: minimal payload (name, description, start/end, status)
    - draft/archived: 404
- Dashboard detail (authenticated lecturer) continues to access full data for all states.

### Join + archived results
- Add endpoints:
  - `POST /courses/{courseId}/join` (allowed only when live).
  - `POST /courses/{courseId}/leave` (optional cleanup).
- Participant definition: only manual join.
- Store session token from cookie, fallback to anonymous token if missing.
- For archived results:
  - Allow `GET /courses/{courseId}/quizzes/{quizId}/results` only if participant joined.
  - For non-participants, return 404 or 403.

### Destructive actions -> kick-out
- Extend `CourseFeedService` to broadcast a new SSE event `course_kick`.
  - Payload: `{ reason, status, effectiveAt }`.
- Trigger on: pause, archive, delete.
- Ensure existing feed SSE continues to work.

### OpenAPI updates
- Update `apps/web/server-schema.yml` with:
  - New fields in `CourseSummary`/`CourseDetail`.
  - New endpoints for lifecycle + join + kick.
- Regenerate client: `bun run openapi:generate` in `apps/web`.
