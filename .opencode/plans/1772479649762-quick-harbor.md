# Plan: Module Ordering + LIFO Reveal/Hide + Lecturer Stats SSE

## Goals
- Add draft-only module ordering (vertical drag and drop) persisted in DB.
- Enforce LIVE-only LIFO reveal/hide based on the draft order (stack controls in UI).
- Add lecturer-only stats section on `/dashboard/courses/:uuid` with separate SSE channel, backed by DB (not duplicated).
- Track total material interactions from student course page (both URL visits + file downloads) and include in stats.

## Backend Changes

### 1) Module ordering (draft)
- Add `orderIndex` column to module entity.
  - Update `apps/server/src/main/java/eu/hypnomacka/timeout/server/core/Module.java`.
  - Use `@Column(nullable = false)` + `@DbDefault("0")` and default `0`.
- On module create, set `orderIndex` to max+1 for the course.
  - Update `apps/server/src/main/java/eu/hypnomacka/timeout/server/controllers/course/modules/ModuleController.java`.
- Update all module listings to sort by `orderIndex`, then `createdAt` for tie-break.
  - `ModuleController.listModules`.
  - `apps/server/src/main/java/eu/hypnomacka/timeout/server/controllers/course/CourseGetController.java` (`buildModuleResponse` callers + archived filtering).
- Add reorder endpoint (draft-only, lecturer-only):
  - `PUT /courses/{courseId}/modules/order` with body `{ moduleIds: [uuid, ...] }`.
  - Validate same count as course modules + all belong to course.
  - Set `orderIndex` in order and save.
  - Add schema + client generation.
- Ensure duplicate course copies `orderIndex` so draft order is preserved in the clone (stats still not duplicated).
  - Update `apps/server/src/main/java/eu/hypnomacka/timeout/server/controllers/course/CourseDuplicateController.java`.

### 2) LIFO reveal/hide in LIVE
- Enforce ordered reveal:
  - In `ModuleController.revealModule`, only allow reveal if module is the next unrevealed by `orderIndex`.
  - Keep reveal LIVE-only + content checks.
- Add collection-level stack endpoints (lecturer-only, LIVE-only):
  - `PUT /courses/{courseId}/modules/reveal-next` → reveals next module (same validations), returns module.
  - `PUT /courses/{courseId}/modules/hide-last` → hides last revealed module (max revealedAt/orderIndex), returns module.
- Emit SSE events via `CourseFeedService`:
  - Keep `module_revealed`.
  - Add `module_hidden` with `{ moduleId, title, hiddenAt }`.
- Update SSE authorization logic remains as-is (feed stream already allows lecturer always, students only when LIVE).

### 3) Course stats storage + SSE (lecturer only)
- New entity `CourseStats` with one row per course:
  - Fields: `uuid`, `course`, `totalSubmissions`, `totalScoreSum`, `totalMaxScoreSum`, `totalPercentageSum`, `materialInteractions`, `updatedAt/createdAt`.
  - File: `apps/server/src/main/java/eu/hypnomacka/timeout/server/core/CourseStats.java`.
- New `CourseStatsService` to get/create stats and update aggregates:
  - `recordQuizResult(course, result)` updates totals and computes % sum.
  - `recordMaterialInteraction(course)` increments interactions.
  - On update, broadcast SSE only if course is LIVE.
- New SSE channel service:
  - `CourseStatsSseService` mirroring `CourseFeedService` emitter handling.
- New controllers:
  - `GET /courses/{courseId}/stats` (lecturer-only; works in any status). Returns averages and totals from DB.
  - `GET /courses/{courseId}/stats/stream` (lecturer-only). Emits `connected` + `stats_update` events.
- Hook stats updates into:
  - `QuizSubmitController` → `recordQuizResult` after saving result.
  - New `MaterialInteractionController` for student clicks.

### 4) Material interaction tracking
- Add `POST /courses/{courseId}/materials/{materialId}/interactions`:
  - Validate course exists + LIVE + material belongs to course + module visible.
  - Accepts no body; increments `materialInteractions`.
  - Response `{ status: "ok" }`.
- Use on student course page only (no dashboard interactions).

### 5) OpenAPI + client generation
- Update `apps/web/server-schema.yml`:
  - Add `orderIndex` to `Module` schema.
  - Add reorder endpoint and request schema.
  - Add stats endpoints + `CourseStats` schema.
  - Add material interaction endpoint.
- Run `bun openapi:generate` (later, during implementation) to regenerate `apps/web/src/api-client`.

## Frontend Changes
- Use the frontend-design, vercel-composition-patterns, vercel-react-best-practices and web-design-guidelines skills

### 1) Draft ordering UI (DnD)
- Use `@dnd-kit/core` + `@dnd-kit/sortable` (vertical-only constraint).
  - Add dependency via `bun add @dnd-kit/core @dnd-kit/sortable`.
- Update `apps/web/src/components/courses/course-modules-section.tsx`:
  - Maintain local ordered modules state synced from query.
  - Wrap module list with `DndContext` + `SortableContext`.
  - Use drag handle + `restrictToVerticalAxis`.
  - Persist order via reorder mutation on drop.
  - DnD enabled only when course is `draft`.

### 2) LIVE stack controls
- Replace per-module reveal buttons with top-level stack controls:
  - "Reveal next module" (disabled if none or next is empty).
  - "Hide last revealed" (disabled if none revealed).
  - Show next/last module metadata in UI.
- Hook to new endpoints (`reveal-next` / `hide-last`).
- Still show per-module status badges (Revealed/Hidden).

### 3) Lecturer stats section
- New component `apps/web/src/components/courses/course-stats-section.tsx`:
  - Styled stats panel (dark, motion.dev) with cards for avg score, avg percentage, total material interactions.
  - Uses query for initial stats and SSE hook for live updates.
- New hook `apps/web/src/hooks/use-course-stats-stream.ts`:
  - `enabled` flag (only connect when course is LIVE).
  - `EventSource` to `/courses/{courseId}/stats/stream`.
  - Emits parsed `stats_update` payload.
- Wire into `apps/web/src/app/dashboard/courses/[uuid]/dashboard-course-client.tsx`:
  - Insert stats section between actions and feed.
  - Connect SSE only when `course.status === live`.

### 4) SSE module hide updates
- Update `apps/web/src/hooks/use-course-feed-stream.ts` to also listen for `module_hidden`.
- Update `apps/web/src/components/courses/course-feed.tsx` API to signal module visibility changes so both dashboard + student pages invalidate queries on reveal/hide.

### 5) Material interaction tracking (student page)
- Update `apps/web/src/app/courses/[uuid]/course-detail-client.tsx`:
  - Replace direct anchor behavior with click handler that calls interaction mutation then opens URL/file in new tab.
  - Use generated API client mutation for interactions.
  - Apply to both URL and file materials.
