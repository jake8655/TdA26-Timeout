# Plan

## 1. Public course access: remove archived student paths
- Make public `GET /courses` and `GET /courses/{uuid}` behave the same for everyone, regardless of lecturer cookie. Public pages should only expose non-archived courses; dashboard keeps using lecturer-only endpoints.
- In `apps/server/src/main/java/eu/hypnomacka/timeout/server/controllers/course/CourseGetController.java`, remove archived-student exceptions and delete the archived-only response helpers used to show quiz results after archive.
- In `apps/server/src/main/java/eu/hypnomacka/timeout/server/controllers/course/quizzes/QuizResultsGetController.java`, block non-lecturers from archived quiz results completely; keep lecturer archived access unchanged.
- Remove the now-dead archived-student tracking path: stop writing `hasSubmittedQuiz` in `apps/server/src/main/java/eu/hypnomacka/timeout/server/controllers/course/quizzes/QuizSubmitController.java`, delete the field from `apps/server/src/main/java/eu/hypnomacka/timeout/server/core/CourseJoin.java`, and drop the column with an Ebean-generated migration.
- Delete the archived student UI branch in `apps/web/src/app/courses/[uuid]/course-detail-client.tsx` and remove `apps/web/src/components/courses/course-archived-results.tsx` if nothing else uses it.

## 2. Public vs lecturer API surface
- Keep lecturer dashboard behavior on lecturer-only endpoints such as `GET /courses/lecturer` and `GET /courses/lecturer/{uuid}`.
- Split feed endpoints if needed so public `/courses` pages only use live/public-safe data, while dashboard feed access can keep lecturer-only archived visibility without leaking through public endpoints.
- Review any public-page calls that still branch on lecturer session and normalize them to public behavior first, dashboard behavior second.

## 3. Remove scheduled end entirely, keep scheduled start
- Remove `scheduledEndAt` from `apps/server/src/main/java/eu/hypnomacka/timeout/server/core/Course.java` and delete all server logic that reads, validates, saves, or returns it.
- In `apps/server/src/main/java/eu/hypnomacka/timeout/server/services/CourseLifecycleService.java`, keep scheduled start automation but delete the automatic end/archive scheduler branch.
- In `apps/server/src/main/java/eu/hypnomacka/timeout/server/controllers/course/CourseLifecycleController.java`, change schedule/start/pause payloads so courses no longer require or accept an end time; manual archive remains the only way to end a course.
- Update server responses in `apps/server/src/main/java/eu/hypnomacka/timeout/server/controllers/course/CourseGetController.java` and `apps/web/server-schema.yml`, then regenerate the web API client.
- Remove end-time UI and copy from `apps/web/src/components/courses/course-schedule-dialog.tsx`, `apps/web/src/components/courses/course-actions.tsx`, `apps/web/src/app/dashboard/courses/[uuid]/dashboard-course-client.tsx`, `apps/web/src/components/courses/course-card.tsx`, `apps/web/src/components/courses/course-header.tsx`, and `apps/web/src/app/courses/[uuid]/course-detail-client.tsx`.
- Drop the `scheduled_end_at` column with an Ebean-generated migration.

## 4. Feed/SSE: keep only lecturer posts + module reveal/hide feed items
- Treat visible feed content as exactly two categories: manual lecturer posts and automatic module reveal/hide posts.
- In `apps/server/src/main/java/eu/hypnomacka/timeout/server/controllers/course/modules/ModuleController.java`, persist reveal/hide actions as feed events so REST history and visible live updates match.
- Remove all other persisted/displayed feed noise on the server: course lifecycle system posts and any non-module automatic feed entries.
- Keep lifecycle control SSE signals for dialogs such as kick/pause/archive/delete, but keep them out of feed history and out of rendered feed items. These should remain ephemeral stream events only.
- Update `apps/server/src/main/java/eu/hypnomacka/timeout/server/controllers/feed/CourseFeedService.java`, `apps/server/src/main/java/eu/hypnomacka/timeout/server/controllers/feed/CourseFeedController.java`, and `apps/server/src/main/java/eu/hypnomacka/timeout/server/utils/EventPersistListener.java` so visible feed history + feed item SSE only emit the allowed items, while separate control events can still trigger dialogs.
- Update `apps/web/src/hooks/use-course-feed-stream.ts`, `apps/web/src/components/courses/course-feed.tsx`, and `apps/web/src/app/courses/[uuid]/course-detail-client.tsx` to keep dialog-trigger events without rendering them as feed messages.

## 5. Split material interactions into downloads + site visits
- Replace the single `materialInteractions` stat with two separate stats in `apps/server/src/main/java/eu/hypnomacka/timeout/server/core/CourseStats.java` and drop the old column via an Ebean-generated migration. No backward-compatibility data mapping needed.
- Update `apps/server/src/main/java/eu/hypnomacka/timeout/server/services/CourseStatsService.java` and `apps/server/src/main/java/eu/hypnomacka/timeout/server/controllers/course/CourseStatsController.java` to expose `downloads` and `siteVisits` separately, including the lecturer stats SSE payload.
- In `apps/server/src/main/java/eu/hypnomacka/timeout/server/controllers/course/materials/MaterialInteractionController.java`, increment downloads for file materials and site visits for URL materials.
- Update `apps/web/server-schema.yml`, regenerate the client, then update `apps/web/src/app/courses/[uuid]/course-detail-client.tsx` and `apps/web/src/components/courses/course-stats-section.tsx` to send/render the two stats separately.

## 6. Migration + regeneration order
- First remove `scheduledEndAt`, `hasSubmittedQuiz`, and `materialInteractions` from the server entities.
- Run `./gradlew generateMigration` so Ebean creates the migration that drops obsolete columns and adds the new stats columns.
- Update `apps/web/server-schema.yml` to match the new server payloads, then run `bun openapi:generate`.
- Finish the web cleanup only after regenerated client types are in place.

- Run `./gradlew build`.
- Run `bun openapi:generate` and `bun types`.
- Manual smoke checks:
- Public `/courses` excludes archived courses for logged-out users, student sessions, and lecturer sessions alike.
- Public `/courses/{uuid}` returns not found for archived courses, while dashboard lecturer pages still show archived results/statistics.
- Starting/scheduling a course no longer asks for or stores an end time; scheduled start still works; only manual archive ends the course.
- Feed history + rendered live feed show only lecturer posts and module reveal/hide posts.
- Kick/pause/archive/delete lifecycle dialogs still trigger from SSE control events, but those events do not appear as feed messages.
- Material stats show separate download and site-visit counters and increment from the correct actions.
