# Multi-country central deployment plan

## Goal
- Move from single-tenant lecturer app to central multi-country deployment.
- Add URL-based tenancy (`/[country]`), central admin management, branch managers, and branch-scoped lecturer access.
- Keep rollout low-risk: additive schema first, dual-compat endpoints, then route migration.

## Confirmed product decisions
- Country URL identity: ISO code + numeric id combined (recommended key: `iso-id`, e.g. `de-12`).
- `/` behavior: redirect to configured default country.
- Manager login: support both localized and global URLs.
- Persistence: single database with tenant keys.
- Course export/import: JSON with attachment URLs only.
- Attachment durability: do not hard-delete assets; keep URLs recoverable.
- Version history: linear snapshot-per-version model.

## Target architecture

### Tenancy model
- `country` is top-level tenant namespace, `branch` is operational unit.
- Every branch belongs to one country.
- Every branch has exactly one lecturer account and one manager account.
- Courses are branch-local (not global). Region is branch metadata for grouping/filtering.

### Identity and roles
- Introduce role-based accounts: `ADMIN`, `MANAGER`, `LECTURER`.
- Replace lecturer-only session linkage with account-based session context.
- Session carries role + scope (`country_id`, `branch_id` when applicable).

### URL map
- Global:
  - `/` -> redirect to default country key
  - `/admin` (admin app shell)
  - `/manager/login` (global manager login)
  - `/login` (global login fallback)
- Localized:
  - `/[country]/login` (localized login)
  - `/[country]/manager/login` (localized manager login)
  - `/[country]/[branch]/dashboard`
  - `/[country]/[branch]/dashboard/courses/[uuid]`
  - `/[country]/[branch]/courses`
  - `/[country]/[branch]/courses/[uuid]`
- `country` param format: `iso-id` (example: `cz-5`).
- `branch` param format: numeric id or stable slug-id (`brno-hq-44`); recommend slug-id for readable URLs.

## Data model and migrations (server)

### New/updated entities
- New `Account`
  - fields: `uuid`, `username` (unique), `hashed_pass`, `display_name`, `role`, `status`, timestamps.
- New `Country`
  - fields: `id`, `iso_code`, `name`, `status`, timestamps.
- New `Branch`
  - fields: `id`, `country_id`, `name`, `city`, `address`, `postal_code`, `region`, `type`, `status`, `manager_account_uuid`, `lecturer_account_uuid`, timestamps.
  - constraints: unique lecturer per branch, unique manager per branch, FK to country/accounts.
- Update `Session`
  - replace `lecturer_uuid` usage with `account_uuid`.
  - add optional scope columns `country_id`, `branch_id` and role snapshot.
- Update `Course`
  - add tenant keys: `country_id`, `branch_id` (required after backfill).
- New `CourseVersion`
  - fields: `uuid`, `course_uuid`, `version_no`, `snapshot_json`, `created_by_account_uuid`, `reason`, timestamps.
- New `FileAsset` for durable attachment addressing
  - fields: `uuid`, `storage_key`, `checksum`, `mime_type`, `size_bytes`, `retention_state`, `deleted_at` nullable.
  - `FileAttachment` references `asset_uuid`.

### Migration sequence
1. Additive migration: create new tables + nullable new columns.
2. Backfill migration:
   - create default country + default branch.
   - convert existing lecturer records to accounts with `LECTURER` role.
   - map existing sessions and courses to default tenant scope.
3. Dual-read period: backend reads new columns first, fallback old linkage if missing.
4. Enforcement migration: make tenant keys non-null, enforce unique/FK constraints, remove legacy assumptions.
5. Generate all schema SQL via `./gradlew generateMigration` (no manual SQL authoring).

## Backend API plan

### Authentication and profile
- Extend `/auth/login` to authenticate account roles and return tenant-aware session.
- Add localized login endpoint `/tenants/{countryKey}/auth/login`.
- Keep `/auth/logout` and `/auth/me`; upgrade `/auth/me` payload:
  - `role`, `username`, `displayName`, `countryKey`, `countryId`, `branchId`, `branchName`.

### Admin capabilities (`/admin`)
- Countries:
  - `GET /admin/countries`
  - `POST /admin/countries`
  - `PUT /admin/countries/{countryId}`
  - `DELETE /admin/countries/{countryId}`
- Branches:
  - `GET /admin/branches`
  - `POST /admin/branches`
  - `PUT /admin/branches/{branchId}`
  - `DELETE /admin/branches/{branchId}`
- Branch account management:
  - `POST /admin/branches/{branchId}/manager`
  - `POST /admin/branches/{branchId}/lecturer`
  - `PUT /admin/accounts/{accountId}/credentials` (username/password/display name)

### Manager capabilities
- Branch edit endpoint scoped to own branch.
- Lecturer credential update endpoint scoped to own branch.
- Authorization: manager can mutate only branch and lecturer within session scope.

### Tenant-scoped course endpoints
- Move to scoped paths:
  - `GET/POST /tenants/{countryKey}/branches/{branchId}/courses`
  - `GET/PUT/DELETE /tenants/{countryKey}/branches/{branchId}/courses/{courseId}`
  - nested modules/materials/quizzes/feed/lifecycle under same prefix.
- Keep temporary compatibility aliases during migration with redirects/deprecations.

## Frontend plan (web)

### Routing and guards
- Introduce dynamic route groups under `src/app/[country]/[branch]/...`.
- Add `src/app/admin/...` for central admin UI.
- Add manager login routes:
  - `src/app/manager/login/page.tsx` (global)
  - `src/app/[country]/manager/login/page.tsx` (localized)
- Add `apps/web/middleware.ts` for early country/branch key validation and route gating.

### Auth state changes
- Expand `use-auth` schema with role + tenant context.
- Replace hardcoded lecturer redirects with role-aware redirects:
  - admin -> `/admin`
  - manager/lecturer -> localized scoped dashboard URL
- Convert raw auth fetch calls to generated API client where practical (or keep temporary bridge until OpenAPI updates land).

### Navigation and link generation
- Replace hardcoded absolute links (`/dashboard`, `/courses`, `/login`) with tenant-aware helpers.
- Ensure header/footer/actions preserve country/branch context.

### Admin and manager UI surfaces
- Admin pages:
  - country list/create/edit/delete
  - branch list/create/edit/delete
  - manager + lecturer credential management
- Manager pages:
  - branch profile edit
  - lecturer username/password edit

## Course export/import plan

### Export
- Add export endpoint returning JSON artifact:
  - includes course metadata, modules, attachment descriptors, quizzes/questions.
  - excludes version history and posts/events.
- Attachment entries include durable URLs and optional internal asset ids.

### Import
- Add import endpoint that validates JSON schema and creates a new draft course in target lecturer branch.
- Preserve module order and attachment references.
- Reject malformed/incompatible payloads with clear error messages.

### Attachment durability requirement
- Switch deletion semantics to soft-delete references/assets.
- Serve files via stable asset URL path so exported URLs remain accessible after source content removal.
- Add delayed cleanup/restore workflow for unreferenced assets.

## Course version history plan
- Use immutable full snapshots per version (linear sequence).
- Create a new version after successful course-mutating operations:
  - course metadata edits
  - module/material/quiz mutations
  - lifecycle changes
  - imports/duplicates
- Store snapshot in `course_versions.snapshot_json` with monotonic `version_no` per course.
- Expose read endpoints for list + detail; no restore/undo in this phase.

## Rollout phases
1. Schema foundation + account/session refactor (no route breakage).
2. Role/scope authorization service and tenant-aware backend endpoints.
3. Frontend route migration to `/{country}/{branch}/...` + admin/manager shells.
4. Course export/import + durable asset model.
5. Version snapshots + history APIs/UI.
6. Remove legacy single-tenant paths and dead code.

## Verification plan

### Backend verification
- Run: `./gradlew build`
- Validate admin flow:
  - login admin, create country, create branch, assign manager and lecturer.
- Validate manager flow:
  - login via both `/manager/login` and `/{country}/manager/login`.
  - update branch fields and lecturer credentials.
- Validate lecturer flow:
  - login localized, CRUD only own branch courses.
- Validate authorization boundaries:
  - cross-tenant URL tampering returns forbidden.

### Frontend verification
- Run: `bun openapi:generate`
- Run: `bun lint`
- Run: `bun types`
- Run: `bun run build`
- Manual checks:
  - `/` redirects to default country.
  - `/{country}/{branch}` routes render and keep context through navigation.
  - admin pages manage countries/branches/accounts.
  - manager can edit branch + lecturer creds only in own branch.

### Import/export + versioning verification
- Export a course with modules + attachments + quizzes; confirm posts/history excluded.
- Import JSON into another lecturer branch; confirm structure parity.
- Delete source material reference; confirm exported/imported attachment URL still resolves.
- Perform several edits; confirm linear version numbers increment and snapshots are retrievable.

## Implementation notes
- Keep compatibility wrappers for legacy endpoints until frontend migration finishes.
- Prefer central authorization helper/service over repeated controller checks.
- Keep changes atomic by phase to reduce rollback blast radius.
