# Student username + lecturer answers + certificate plan

## Scope locked from user
- Certificate threshold: per-course only.
- Retakes for points: best attempt per quiz.
- Username: per-course session, locked after first set.
- Duration: quiz open -> submit (per attempt).
- Lecturer participant list: one button per student, latest attempt view.
- Certificate PDF content: name + course + issue date.

## Implementation approach (recommended)

### 1) Backend data model + migration
- Update `apps/server/src/main/java/eu/hypnomacka/timeout/server/core/CourseJoin.java`
  - add `username` (nullable), stored per `(course, sessionToken)`.
  - lock semantics enforced in controller (cannot change once set).
- Update `apps/server/src/main/java/eu/hypnomacka/timeout/server/core/QuizResult.java`
  - add `attemptStartedAt` (`Instant`, nullable).
  - add `durationSeconds` (`Integer`, nullable).
- Generate migration via entity changes only:
  - `./gradlew generateMigration`
  - do not hand-write SQL.

### 2) Backend API changes
- Extend `POST /courses/{courseId}/session` in `apps/server/src/main/java/eu/hypnomacka/timeout/server/controllers/course/CourseSessionController.java`
  - accept optional body `{ username?: string }`.
  - if join has no username and request has username -> save username.
  - if join already has username and request tries different username -> `409`.
  - response includes `sessionId`, `username`, `usernameLocked`.
- Extend submit flow in `apps/server/src/main/java/eu/hypnomacka/timeout/server/controllers/course/quizzes/QuizSubmitController.java`
  - request adds `attemptStartedAt`.
  - compute `durationSeconds = submittedAt - attemptStartedAt` (clamp invalid/future to null).
  - keep score logic unchanged (already 1 point per correct answer).
- Extend lecturer results endpoint in `apps/server/src/main/java/eu/hypnomacka/timeout/server/controllers/course/quizzes/QuizResultsGetController.java`
  - add query param `latestPerParticipant`.
  - lecturer mode returns enriched items with:
    - participant identity (`sessionToken`, `username`),
    - duration,
    - submitted answers per question (`selectedIndices`) for that attempt.
  - when `latestPerParticipant=true`, return one latest attempt per participant.
- Keep `GET .../stats` in `apps/server/src/main/java/eu/hypnomacka/timeout/server/controllers/course/quizzes/QuizStatsGetController.java` as current “All” aggregate source.

### 3) New backend endpoints (student progress + certificate)
- Add `GET /courses/{courseId}/progress`
  - file: new controller under `apps/server/src/main/java/eu/hypnomacka/timeout/server/controllers/course/`.
  - derive student by `STUDENT_SESSION_ID` + course join.
  - compute points = sum of best `QuizResult.score` per quiz in this course for this session.
  - return `username`, `points`, `threshold(10)`, `eligible`.
- Add `GET /courses/{courseId}/certificate`
  - validate same session and `eligible == true`.
  - return PDF bytes with `Content-Type: application/pdf` + attachment filename.
  - if not eligible return `403` with `{status:"bad", message:"..."}`.
- Add service(s) under `apps/server/src/main/java/eu/hypnomacka/timeout/server/services/`
  - progress calculator (best-attempt aggregation).
  - PDF generator service (Apache PDFBox dependency in `apps/server/build.gradle`).

### 4) Frontend student flow changes
- Update `apps/web/src/components/tenant/tenant-course-detail-client.tsx`
  - store session response (`username`, `usernameLocked`).
  - add shadcn dialog for username when starting first quiz without locked username.
  - username submit calls `POST /courses/{courseId}/session` with username.
  - add certificate card/button:
    - fetch `/courses/{courseId}/progress`,
    - enable download only when `eligible`.
- Update `apps/web/src/components/quizzes/course-quiz-card.tsx`
  - before opening quiz dialog, enforce “username locked” gate from parent callback.
- Update `apps/web/src/components/quizzes/quiz-player.tsx`
  - capture attempt start timestamp on open.
  - include `attemptStartedAt` in submit payload.

### 5) Frontend lecturer results UX changes
- Update `apps/web/src/components/quizzes/quiz-stats-dialog.tsx`
  - keep existing stats query for aggregate “All” mode.
  - add results query with `latestPerParticipant=true`.
  - render horizontal/stacked list of buttons:
    - `All` + one per participant username.
  - `All` selected -> current aggregated stats view unchanged.
  - participant selected -> show that student’s chosen answers + duration for latest attempt.
- Update `apps/web/src/components/quizzes/quiz-stats-question.tsx`
  - support both aggregate rendering and participant-selected rendering.
  - participant mode should highlight chosen options and correctness clearly.

### 6) OpenAPI + generated client updates
- Update `apps/web/server-schema.yml` for:
  - session request/response additions,
  - submit request/response additions,
  - enriched quiz results schema + query param,
  - new `/courses/{courseId}/progress` and `/courses/{courseId}/certificate`.
- Regenerate client in `apps/web`:
  - `bun openapi:generate`.

## Verification plan

### Build + generation
- Server:
  - `./gradlew generateMigration`
  - `./gradlew build`
- Web:
  - `bun openapi:generate`
  - `bun lint`
  - `bun types`
  - `bun run build`

### Manual E2E checks
- Student username/session
  - open live course, start quiz -> username prompt appears.
  - set username once, open another quiz -> no prompt.
  - attempt to change username -> backend returns conflict, UI keeps locked name.
- Quiz timing + answers
  - submit quiz -> duration saved and visible in lecturer participant view.
  - score still matches count of correct questions.
- Lecturer quiz dialog
  - sees `All` + participant buttons.
  - click participant -> selected user answers + duration shown.
  - click `All` -> existing aggregate stats view restored.
- Points + certificate
  - retake quiz with lower score does not reduce points (best attempt rule).
  - points computed per course only.
  - once points >= 10, certificate button enables and downloads PDF with name/course/date.

## Risks and mitigations
- Username collisions: acceptable (display label only), identity source remains session token.
- Tampered client start time: duration nullable fallback, never blocks submit.
- Legacy rows without new fields: keep columns nullable + optional rendering in UI.
- Large lecturer payloads: `latestPerParticipant=true` limits results size.
